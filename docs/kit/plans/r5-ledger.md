# Round 5 revision ledger

_Integrator: Claude Opus 5.5 (Claude Code), 2026-10-07, judging Google Gemini 3.1 Pro's round-5 revisions to `10-plan.md` for Mike Wolf's SOMA brain trust._

| Revision ID | Title | Decision | One-line reason |
|---|---|---|---|
| R1 | Eliminate redundant outbox architecture for shared-database writes | Somewhat agree | Verified that `register` creates the app schemas in the shared project, so one transaction suffices. Kit apps had no write path that bypassed the broker anyway, so the outbox never helped during a broker outage. I specified that the broker opens the transaction itself, because the app RPC's owner cannot write `soma`. I kept "idempotently" and added a unique `(app_id, kind, app_record_id)`. I added a retry path for legacy apps that commit outside the broker. I also updated the decision row, `receipt_index`, §3.2, C15 (now with failure injection), M5 and the risk row. |
| R2 | Fix the transaction contradiction for action execution | Somewhat agree | Verified that PlayMaker's `agent-v1.ts` claims, runs, and settles in three separate PostgREST requests, so the plan's "one transaction, as PlayMaker already does" was false. Rather than giving up atomicity, a database effect now runs as a single app RPC that claims, applies, and settles in one transaction, which works because receipts and domain tables share the app schema. External effects use separate calls plus reconciliation. |
| R3 | Decouple contract updates from manual steward registration | Somewhat agree | The broker enforces the contract hash, so an auto-deployed manifest change would break until the steward acted. But the runtime installation credential should not rewrite its own registration, and the revision deleted the migration-safety and staging-only-alias text without any reason. `sync-contract` now uses a build-only release credential. The broker recomputes the hash and refuses changes to origins, `identity.subject`, unregistered `soma:*` entries, provisioning, and unapplied migrations. It accepts the previous hash during the switch. C12, §2.9, M3 and §8.2–8.3 are updated to match. |
| R4 | Remove user-only UI routes from the AI Visitor Discovery | Agree | Only the signed-in principal can decide an approval, so the route belongs with the person-facing routes. I also stated that it is session-plus-CSRF only and never appears in discovery, `llms.txt`, or OpenAPI. |
| R5 | Make privacy data flows an executable gate rather than prose | Somewhat agree | A machine-checkable retention field is right. But the revision wrote "zero-retention" and "30-days" for Anthropic, and those are claims that only the operator's vendor agreement can support. I used `retention_days` (an integer or `"undeclared"`): a prototype that leaves it undeclared gets a warning, and public MVP fails on it. The legal pages render from the field so the prose cannot drift, and C18 checks that. |
| R6 | Ensure critical errors reach the steward without a shared service | Somewhat agree | Verified that today's crash alarm (`_estate/crash-alarm/`) reads PlayMaker's feedback tables with the shared secret key, a path M11 removes. Forwarding every crash would flood the inbox, so only a new fingerprint per release and each tenfold rise are filed. Each event carries fingerprint, route, release, and count only. It is written in the same broker transaction, and the inventory row is updated to match. |

Applied: 1 agree, 5 somewhat, 0 disagree.
